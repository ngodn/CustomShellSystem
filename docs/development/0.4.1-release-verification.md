# CSS 0.4.1 release verification

A patch on 0.4.0. No format, schema or ABI change. CSSX, UI Kit and Cheat Menu
remain at 0.3.0, and outfit packages built for 0.4.0 need nothing.

## What it fixes

0.4.0 shipped the COLOR swatch strip invisible, because `flat_button()` clears
every brush a CSS button has and the chips were buttons with a background colour
set on them. That was found in game, not by a test, and it led straight to the
serious one: the grid pushed the page past the default 64-child limit in
`inventory_children(canvas)`, the guard threw from inside the panel build, and
CSS reported itself unavailable and left the inventory tab strip, taking CSSX
with it. Reproduced from `CSS.log`:

```
Core activated: css_core-swatchfix-…
Inventory CSS unavailable: Inventory child count out of bounds
```

Three changes, in order of what matters:

1. That call is wrapped. It drives the slide-in when the tab opens and nothing
   else, so a failure there now costs the animation, not the wardrobe.
2. The limit is 256, matching what the extension page already allows. The guard
   is for a runaway panel, not for capping a page at a screenful.
3. The grid is two widgets per chip rather than three, and 56px in six columns
   rather than 84px in four, which also stops it colliding with the buttons
   beneath it.

Plus a labelling fix: a part the selected palette does not set no longer claims
that palette's name.

## Runtime

The fixed core was hot-loaded into the running game and confirmed by the player:
swatches render, and the CSS and CSSX tabs stay on the strip while scrolling
through every colour part. That core is the same source as the one in the ZIP.
