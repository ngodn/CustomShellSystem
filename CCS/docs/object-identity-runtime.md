# Engine object identity

General `engine::ObjectHandle` captures now require a positive object-array serial. Resolution checks index, pointer, serial, live flags and name. A zero serial cannot distinguish generations when an object-array slot and allocation are reused, even if the new object has the same name. No zero-serial handle can become a reflection-cache owner or a published engine guard.

Cold capture initializes a missing serial through the engine's native static `Conv_ObjectToSoftObjectReference`. It checks the object's live entry before and after that call. It neither assigns a serial itself nor loads an asset. The pinned SDK's `FUObjectArray::AllocateSerialNumber` uses the same conversion as a side effect; the retained UE 5.6.1 weak-pointer source requires a real allocated serial.

This initializer uses a dedicated uncached `Call::Cache::SerialInitializer` path. It accepts only the expected Kismet owner/function, validates native/static/nondelegate flags, two parameters, object/soft-object property kinds, input class, directions and nonoverlapping bounded storage before initializing the parameter values. It does not capture cache-owner identities or use the normal reflection-call cache. A reentry guard rejects nested cold initialization rather than recursing. `WeakObject` uses the same setup, then assigns the SDK weak pointer after the serial exists.

Normal reflected calls cache guarded owners and guarded UFunctions. Each Call stores up to 64 parameter pointers in its own fixed array rather than borrowing a cache entry's vector. It captures the target identity, rechecks target/function identities before ProcessEvent, and destroys only successfully initialized parameter values, in reverse order. Native execution and GC/reentry behavior of the revised path still require live checks.

Hook callbacks use `capture_existing`, which never initializes a serial. Probe 03 uses only already-cached object fields for generation checks; a missing/expired cache entry cancels observation. An ability or montage without an existing positive identity is skipped, with `identity_skipped` in status and the terminal trace. This may omit a newly created execution instance before the engine assigns its first weak serial. Actual coverage must be measured; skipped identities cannot establish an observed ability lifetime, slot or compatibility. The report also requires positive serials and valid integer indexes before marking live references observed.

LoadedMoves now captures one initial grant per tick rather than initializing all grant identities in startup. It preserves the prior completed snapshot during an unchanged refresh and still rechecks every captured grant afterward. Class-map construction and prior-instance transfer happen in that same bounded phase. The 30-second capture timeout and measured 2 ms cutoff remain, including the added phase. These bounds cannot preempt a slow engine call or guarantee FPS.

The running game's read-only function description confirmed an eight-byte object input and a forty-byte soft-reference return. Raw acknowledged queries are retained in `CCS/work/object-identity/serial-interface.json`. This checks two interface sizes only, not the revised initializer, serial allocation, cache reuse, hook coverage, GC/travel behavior or performance. The candidate remains uninstalled pending a fresh stopped-playing confirmation.
