# CSS 0.4.0 release verification

Only CSS is updated. CSSX, UI Kit and Cheat Menu remain at 0.3.0. The outfit
package format stays v1 and the extension ABI is unchanged. The saved-state
schema stays 1: a saved look gains an optional `tints` object, and a colour
control gains the optional `group`, `role` and `hue_locked` fields.

## Source and build

- Release work: `8b3bb1b`.
- Annotated tag `v0.4.0`, source commit `1355008aae9e5e5024adbcb2c5283cd48baabe25`.
- Built by `tools/css_release.py build`, which refuses any revision but the tag
  and any tree that is not clean. Pinned UE4SS SDK `d7e7826d`.
- Release Windows x64 loader and core built with `CSS_INVENTORY_DEV=OFF` and
  `CSS_TRANSITION_TESTS=OFF`. The development configuration (`CSS_INVENTORY_DEV=ON`)
  builds clean as well, with no warnings in CSS sources.
- 56 Python tests and all nine native test groups pass. `css_colors` covers 52
  colour behaviour checks, including the new `choose_palette` rule and the group,
  role and hue-lock resolution for both declared and inferred recipes.

## Backward compatibility

The risk this release carries is that every package published before it has no
`group`, `role` or `hue_locked` on any colour control, and CSS now has to infer
all three. `tests/package_tests.cpp` prints what it resolved, and was run against
every package installed on the development machine.

| package | resolved |
| --- | --- |
| BeauteGenessa | clothing garment, metal *locked*, skin *locked*, face, eye-glow, eye-intensity |
| BeauteKnightLady | armor garment, metal *locked*, cloth garment |
| BHProxima | armor garment, clothing garment, metal *locked*, cape garment |
| CurvyAndCutePROXIMA | armor garment, clothing garment, metal *locked*, skin *locked* |
| HIT2 DE Scyther | clothing garment, metal *locked*, ribbons accent, gems *locked*, skin *locked*, face, hair |
| LongHairProxima | armor garment, clothing garment, metal *locked*, skin *locked*, hair |
| MileenaOverTiel | clothing garment, metal *locked*, skin *locked* |
| Seductress V1 | cloth garment, metal *locked*, skin *locked*, face, eyes, eye-glow |
| Seductress V2 | as V1, plus nipple, areola, labia and vestibule on the variants that bare them |
| Seductress V2.1 | silk and cloth garment, trim accent, metal *locked*, skin *locked*, hair, glow, glow-strength, eyes, eye-glow |

Ten packages, ten passes, every control landing in a sensible group with the
right hue lock. Catalog load, thumbnail, cache reuse, cache repair and pak
corruption rejection pass for all ten as well.

One thing the survey shows and the inference cannot fix: BeauteGenessa calls its
iris colour `eye-glow` and its scalar `eye-intensity`, so the iris resolves to the
`eye-glow` role. Both are body controls and neither is hue locked, so nothing
behaves wrongly, but it is the kind of drift
[the convention](../color-convention.md) exists to end. Normalising the ports is
tracked separately.

## Outstanding

Runtime checks in the game are the player's, and the build installed for them is
the same core as the one in the ZIP (`css_core-0.4.0.dll`, identical bytes to
`build/release-windows/css_core.dll`). Not yet confirmed in game: the new swatch
picker, the group tints, the intimate colour controls on Seductress V2, and the
rebuilt skin on both V2 bodies.
