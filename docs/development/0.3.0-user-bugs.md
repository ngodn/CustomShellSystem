## Runtime checks and recovery performance (15 September)

Eight successive Genessa/Tiel/Eredrim switches recovered each selected outfit,
kept the scythe in hand and allowed native Inventory to open and close. The five
checked attack/dodge/aim/menu restriction counts stayed zero. This exercised
retained-pawn shell changes, not death or every original Lua hotkey combination.
Evidence: `work/cssx-native/repeated-shell-recovery.json`.

A real Marrow Keep launcher activation and destination-selection cancellation
kept Seductress V1 applied through all 25 sampled return states. Inventory opened
afterward, with no pending recovery or ignored movement/look input. This does not
cover selecting a destination, beacon cleansing or death.
Evidence: `work/cssx-native/launcher-cancel-live.json`.

_eins0fx then reported a pause near the end of that animation with colored
Seductress V2. Logs showed material recovery taking 801–963 ms. A repeated
material-slot reset reproduced it at 815–842 ms: `apply()` discarded valid color
MIDs and regenerated dye textures even when the outfit had not changed.

The recovery path now reattaches the existing materials after a recognized stock
material reset. It validates every weak reference before writing, preserves
active/unrecognized game effects, verifies the resulting slots, and falls back
to normal rebuilding when resources have been collected. It does not retain old
worlds or change texture resolution. Three repeated runs took 0.23–0.30 ms and
preserved the exact material objects. These are CSS apply timings, not whole-game
frame times or a promise that all loading hitches are gone.

Evidence: `work/cssx-native/color-recovery-before.json`,
`color-recovery-after.json`. Repeatable regression check:
`python3 tests/live_material_recovery_perf.py` with a colored outfit and the
staged developer core. _eins0fx confirmed the natural V2 launcher animation is smooth after the fix.

The same optimization now covers a recognized stock-mesh reset on the retained
pawn. Before: 806–834 ms. After: 2.72 ms, 1.82 ms, 2.70 ms. All runs retained the same color materials.
`python3 tests/live_material_recovery_perf.py --mesh` covers this path.
Three additional stock/empty-MID/active-effect cycles passed with the colored V2
outfit, including Inventory cleanup and unchanged animation instance and saved
preferences. All nine portable test groups passed. New-pawn/death recovery still
requires rebuilding when the old resources no longer exist; its performance is
not established by these retained-pawn tests.

## Blood and shadow checks

A second blood test used the currently colored Seductress V2 outfit. The native
blood-mask value changed while the skeletal mesh and all override-material
objects stayed identical. Removing only `CSS_ColorBloodProbe` restored the test
mask contribution. Saved preferences were unchanged. Evidence:
`work/cssx-native/colored-blood-check.json`. This does not cover every death,
overlay or environmental-effect path.

One directional dodge each with Seductress V1, Beaute Genessa and stock Genessa
on the same gameplay shell in Marrow Keep did not reproduce a persistent shadow
trail in the post-dodge screenshots. Component bounds changed during motion and
settled afterward. Neither fixed skeletal bounds nor parent bounds were enabled;
BoundsScale was 1, shadow-cache behavior was Auto, and capsule shadows were off.
The screenshots were taken after the animation, so a brief motion/temporal trail
still needs a capture during the reported artifact. No shadow-quality or global
bounds workaround was applied. Evidence: `work/cssx-native/*-dodge-bounds.json`
and `*-after-dodge.jpg` for those three appearances.

Epic's [Virtual Shadow Maps documentation](https://dev.epicgames.com/documentation/unreal-engine/virtual-shadow-maps-in-unreal-engine)
explains that deforming geometry invalidates cached shadow pages and displaced
geometry needs sufficient bounds. This is a diagnostic lead, not an established
cause of the reported artifact.

## Leftover dye material after a gameplay-shell switch

The Proxima aiming comparison exposed another CSS recovery blocker. Switching
from colored Seductress V2 on Genessa to stock Proxima left a CSS-created
`MID_MI_Genessa_top` in slot 6, beyond Proxima's six material slots. Its dye texture
parameter caused the active-effect guard to reject outfit changes indefinitely.
The material was CSS-owned, not a story restriction or another mod's effect.

`detach_residual_colors()` now removes only exact live MIDs in CSS's ownership
map when the game has changed that component's mesh. It neither recognizes
ownership by name nor clears unfamiliar effects. The weak dye cache remains
available for temporary stock-mesh recovery; cleanup also runs before unloading.

The regression failed before the fix with that leftover slot, then passed three
Genessa/Proxima/Genessa cycles. The tests preserved appearance preferences and
returned to the original shell. Material-only recovery remained 0.24–0.28 ms and
stock-mesh recovery 1.85–2.06 ms. Three more active/empty-effect cycles and native
Inventory cleanup passed. Run `python3 tests/live_colored_shell_switch_check.py`
with the documented safe-game prerequisites. Evidence:
`work/cssx-native/colored-shell-switch-before.log`, `colored-shell-switch-after.log`,
`proxima-ready-check.log`, and `residual-color-transitions.log`.

## HIT2 repeater comparison

The game's sidearm name is **Triarch Repeater** (`ID_Sidearm_MachineGun`). Aiming
on Genessa with stock and HIT2 appearances kept the weapon-forward pitch close
to horizontal. The first Proxima comparison was invalid because the leftover
CSS dye material above prevented HIT2 from applying. It was repeated after that
fix, with an explicit assertion that the requested appearance had applied.

With Proxima and the same aim input, stock default projectile rotation had a
pitch of 4.16 degrees; HIT2 had 19.16 degrees. Weapon-forward pitch remained about
0.54/0.99 degrees respectively, while its roll changed by about 15 degrees. This
establishes an upward default-projectile alignment difference, not a verified
fired trajectory or proof that every aiming mode uses that default transform.
No universal gun-angle correction was applied.

The source skeletal-mesh `.uexp` and the converted round-trip payload in
`work/convert-hit2-p-final` are byte-for-byte identical: 4,804,774 bytes, SHA-256
`f07b13b38ec0f4b30e33cc0947805ac12374819089d6c1d71f66b8c695c8ee47`.
That check does not replace an in-game original-package comparison or verify
all post-process and firing behavior. Evidence: `work/cssx-native/triarch-aim-check.json`
(Genessa), `triarch-KnightLady-aim-check.json` (valid final Proxima run), and the
matching aim screenshots. The temporary repeater was removed, the Nail Shotgun
restored, and the gameplay shell returned to Genessa after testing.

## Dodge material correction, 15 September afternoon

The white shredded geometry is a material displacement effect. During the same
frozen Harros dodge pose, removing `OverlayMaterial` left the white geometry in
place. Setting only `DarkBro WPO Stretch Scale` from 256 to 0 removed it while
retaining the normal translucent dash overlay. Setting `Shell Explosion WPO
Scale` to 0 did not remove the artifact.

CSS now neutralizes the DarkBro stretch parameter on its owned material
instances when applying/customizing an outfit. These instances share the dye
material ownership and recovery cache. Original assets and unfamiliar dynamic
materials are not edited. Standalone materials, including Beaute Genessa's
cloth drivers, are left intact because they have no material-instance parameter
API. There is no new per-dodge callback or texture rebuild.

The separate native dash overlay and shell-explosion parameter remain intact.
This intentionally disables one native displacement branch on replacement
material instances; it is not a general cloth, shadow-cache or bounds fix.
The precise topology assumption inside the cooked shader is not established.

The read-only regression `tests/live_dodge_material_check.py` failed with scale
256 before the fix and passed with 0 afterward. Controlled Harros captures
compared stock, HIT2 and Seductress before/after. _eins0fx also confirms:
"The shredded-body trail is gone."

Evidence: `work/blood-dodge-investigation/harros-seductress-probe*.jpg`,
`fixed-harros-*.jpg`, `parameter-before.log`, `parameter-after.log`.
A material readback passed for one variant of each of the nine installed
outfits, including Seductress V2 Original and Beaute's standalone cloth drivers.
This is not a visual test of every variant. V2 color reset and restoring its
palette passed; saved preferences were restored unchanged. Three material-reset
recoveries took 0.26-0.35 ms and three retained-pawn stock-mesh recoveries took
58.00-59.93 ms on V2 Original, all reusing the same material objects. The latter
is a different variant from the earlier topless-harness timing and does not
establish equal mesh-reset cost. Both pass the existing 100 ms apply budget;
these are CSS apply timings, not whole-frame or loading-time guarantees.

The final native core built and staged successfully; the nine existing portable
test groups passed during this investigation. The fix is staged in the active
developer core. Published 0.3.0 ZIPs have not been replaced.

## Seductress blood coverage finding

The authoring skin BRM red channel is solid white in both V1 and V2. A controlled
V1 and V2 Original comparison changed only that channel, retaining identical
green/blue channels and
the same material object. The white control reproduced uniform glossy blood
coverage; a diagnostic gradient restricted coverage while clean skin stayed
pale. This identifies a texture-authoring problem, not a requirement to rebuild
the body's geometry. Neither Seductress package was changed.

The investigation, source trace, proposed mask work and copied evidence are in
`CSS-eins0fx-collections/seductressV2-eins0fx-CSS/docs/blood-material-investigation.md`.
Earlier blood tests only established mesh/material identity, not correct visual
coverage. Also, reflected `CustomPrimitiveData` is the serialized default, not
the separate internal runtime array used by the renderer. Do not cite that
property as evidence that runtime blood inputs stayed unchanged.
