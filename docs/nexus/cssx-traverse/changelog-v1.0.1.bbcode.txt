[b]CSSX Traverse 1.0.1[/b] (2026-09-29)

Hey everyone. This one fixes something nasty I ran into myself, so please update.

[size=4][b]What's fixed[/b][/size]
[list]
[*][b]A traverse now tells the game which zone you arrive in[/b], the way the game's own beacons and gates do. Before, the world stayed in the zone you left: enemies spawned wrong there, and a beacon trip taken from that state could corrupt the save so it crashed on every load. If that happened to you, load one of the game's own backups (WorldState_Backup_*.sav next to your save) from before the traverse.[/*]
[*]Traverse waits until a previous traverse has fully arrived before it fires again.[/*]
[*]Traverse refuses to fire from inside a dungeon. Leave through the dungeon's own exit first.[/*]
[*]A point whose zone cannot be read is skipped, and the CSSX tab names it, instead of being fired blind.[/*]
[/list]

[size=4][b]Nerd corner[/b][/size]
[list]
[*]The game's streaming teleport takes an optional zone data asset. Its teleport ability broadcasts "zone changed, reason: player teleported" only when that asset is there, and spawners, ambience and the save's landing area follow that broadcast. 1.0.0 passed nothing. 1.0.1 reads the landing area's own zone, or the gate's, exactly where the game's travel code reads it.[/*]
[/list]
