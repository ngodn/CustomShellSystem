[b]CSSX Traverse 1.0.2[/b] (2026-10-05)

Hey everyone. Two fixes for the "ask before traversing" dialog, both reported by Kantiger. Thanks for the clear steps.

[size=4][b]What's fixed[/b][/size]
[list]
[*][b]Confirming with Space no longer drops a pin on the map.[/b] The map underneath now ignores your keys while the dialog is open, so Space, Enter, E and Escape only talk to the dialog.[/*]
[*][b]You can click Traverse and Cancel with the mouse.[/b][/*]
[*]Hovering an option selects it, so the confirm key always acts on the option that is lit.[/*]
[/list]

[size=4][b]Nerd corner[/b][/size]
[list]
[*]The dialog was meant to switch off the menu's input listeners while it is open, but the check that picks which ones to switch off was wrong, so it never switched any off. The map's pin listener takes the same confirm input as the dialog, which is where the pin came from.[/*]
[*]The mouse clicks did land on the buttons, nothing was reading them. Traverse now reads each button's own state: hovered means selected, clicked means confirmed.[/*]
[/list]
