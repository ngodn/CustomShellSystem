# CSS 1.0.7

CSS 1.0.7 and CSS Shared Assets 1.0.7 ship with Profane Proxima v0.2.3.

- Core: Customize > Body has a Body preset row. Left and right cycle the outfit's body presets, the details panel lists them all, and the row shows Custom once a body slider moves. Body presets no longer appear in the Template row or the template browser.
- Core: shader fallback. `catalog/shader-donors.json` (460 materials, 9 game donors, built by `tools/authoring/shader-donors/build_shader_donors.py` from every released outfit zip and the installed packs) pairs each outfit material that borrows game shaders with the game material of the same permutation. On a game build whose pak tables are not verified (verified: 26147827), or with Misc > Compatibility > Outfit materials set to Always, CSS rebuilds those materials (and child instances without their own permutation) as dynamic instances of the donor and copies their parameters (`K2_CopyMaterialInstanceParameters`, quick). A runtime guard compares Parent, BasePropertyOverrides, StaticParametersRuntime, permutation and subsurface/specular fields and skips any donor that differs. Live test 26 Oct: Auto leaves the verified game untouched; Always draws Eve, Commander White and Profane identically; old Eve 1.5.0 (gray face and skin on 26147827) gets its textures back.
- Core: CSS.log lists the game exe size, Steam build and pak table sizes at startup, each package version, and (when the fallback is on) every material and its donor once per look.
- Shared Assets 1.0.7: released 1.0.4 containers unchanged; metadata pak adds Profane Proxima 0.2.3 (981feb9b91f7) revision pins. Built with `tools/authoring/shared-assets/append_revision_pins.py` and `build_face_rig.py`.
- Game build 26147827: every Profane Proxima 0.2.3 material passes the shader audit with SM5 and SM6.
