# Retained menu rendering

The experimental CCS menu now retains a separate canvas and cell pool for Customize, Preset and Settings, plus a stable preset editor pool. Switching screens changes root visibility. Repainting compares text, color, font size, placement, enabled state and visibility before calling Unreal setters. Ordinary navigation no longer clears the canvas, reparents existing rows or recreates every widget.

Each visible page build creates at most four widgets, including canvas roots and button labels. The editor receives only the page pool's remaining creation budget. Unfinished creation resumes on the next visible-menu tick. Each pool has at most 128 cells, with retained TextBlock/Border/EditableText/Button variants as used. Unused cells and inactive screen roots are hidden. This limit covers CCS pool construction calls, not engine-internal Slate allocations or the separate menu-tab attachment work. Actual frame time still needs measurement.

The menu measures the parent switcher's painted local geometry at most twice per second and waits for a usable extent. The screenshot composition is fitted uniformly and centered in that local space. Widths, heights and font sizes share the smaller of the horizontal and vertical scales, preserving control proportions on ultrawide and narrower pages. Extra space stays outside the composition. The 1920/1080 numbers describe the authoring frame, not assumed viewport dimensions. Geometry is already local to the native widget hierarchy; CCS does not apply a second viewport DPI factor. Invalid or nonfinite extents are rejected. Native slot icons, glyphs, inspection cards and real-game resize/readability checks remain pending.

Fonts are reused only if already loaded. Otherwise a TextBlock gets the live native tab's FontData style. No builder calls LoadAsset_Blocking. Reopening invalidates cached visual values so the active model is reapplied after native reconstruction. Controller/menu replacement releases CPU pool references; construction roots are temporary, and attached widgets belong to the canvas hierarchy.

The move browser shows a window of at most eight records around the selected row; presets show at most fourteen. The selected row remains visible without constructing an entire library. Move and Tarstone slot filters now return prebuilt immutable pointer views instead of scanning and copying strings on every input/build. The manager cannot be copied because it owns those indexed records and any acquired engine roots. Enemy and player views are separate, so an empty enemy browser cannot accidentally select a player move.

Removed from the builders: fixed weapon/enemy sample rows, the fake Stillblade level and perk card, the fake 3D icon label, guessed damage/poise displays and the 0ms performance claim. Empty and missing bindings show their actual states. The extracted research fixture is no longer loaded at runtime. The player browser shows current discovery state and reference counts while eligibility checks remain pending; Tarstone and enemy libraries remain empty. Preset naming, confirmation and errors now use a retained editor; its native focus and button behavior remain unverified. Mapped key names replace fixed text shortcuts, while native glyph integration remains pending. A default preset no longer invents Hadern's Sword as its base weapon.

Design constraints: match the game's dark menu and fonts; keep the selected slot as the focal point; place the two slot rows near the bottom center and the section strip below the left title. ENERGY 2, RHYTHM 2, MOTION 1. No added animation or decorative effect. The visual delivery audit is incomplete until real game rendering, native widget integration and keyboard/controller/mouse/focus states are verified. The default build keeps this prototype disabled.

Reference: [CSSX retained cells](../../extensions/core/src/core/menu_page.cpp), [Epic UMG optimization guidance](https://dev.epicgames.com/documentation/unreal-engine/optimization-guidelines-for-umg-in-unreal-engine), [Epic UE 5.6 DPI scaling](https://dev.epicgames.com/documentation/en-us/unreal-engine/dpi-scaling-in-unreal-engine?application_version=5.6), and [cached geometry caveats](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/UMG/UWidget/GetCachedGeometry). The existing-game implementation and reflected checks, rather than newer documentation alone, determine supported call layouts.

Verification: eleven host suites pass normally and under ASan/UBSan. Layout tests cover 16:9, ultrawide, 16:10, 4:3, portrait, small pages and invalid extents; they check containment, centering, use of the available area, and preserved control/font proportions. Window tests check every selected index for libraries up to 1,024 records, bounded output, no avoidable blank rows, empty windows and size_t overflow boundaries. All seven current CCS Windows variants compile without reported warnings. These tests do not execute Unreal widgets or prove FPS behavior. Native construction, font layout, close/reopen, resize and travel tests require a later stopped-game installation and live run.
