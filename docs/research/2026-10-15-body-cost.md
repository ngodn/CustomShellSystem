# Paired body-solver timing in UE 5.6.1

The isolated editor fixture completes 48 matched enabled/bypassed cases and
28,800 measured animation updates. Both Peony meshes use the accepted tighter
body source, with four alternating-order pairs at each of 30, 60 and 120 updates
per second. Solver counters, public-to-rig enable transfer and finite output
transforms pass. The existing input-handoff regression also passes six cases
and 3,366 frames using the rebuilt module.

These are synchronous editor animation timings. They do not establish shipped
game frame rate or complete the release performance gate.

## Comparison and measurement

The regional Off setting is unsuitable as a solver-cost baseline. In the saved
body graph generator, `controlrig_body_step.py` selects the incoming target when
a region is disabled, after computing the step. `TotalSteps` still advances.
The top-level `Enabled` branch in `build_controlrig_body_timed.py` instead skips
the solver. The new `MeasureBodyCost` fixture sets `CSSBodyEnabled` once on a
transient post-process instance and verifies that the live rig receives it.

The fixture reuses the established `CSSBodyInputs` module, pinned C++20,
UE 5.6.1 CL 44394996 and its Clang 18.1 toolchain. A new small project contains
only module sources and a link to retained Peony editor content. Bubblewrap
mounts that content read-only and overlays the accepted `CR_Body.uasset`
read-only at its canonical load path. Its SHA-256 is
`b3ab641b2dcb73db71ed394135cde55dd7eeaa3762dbbdd8a7662f1a93b97737`.
No assets are saved or cooked.

Each case creates a new transient component, selects its actual saved secondary
AnimBP, disables cloth and update-rate optimization, and applies a repeated
10 cm sinusoidal vertical translation. After two simulated seconds of warmup,
it records 600 updates. Four pairs use Off/On, On/Off, Off/On, On/Off order.
The comparison changes only the body-enable value. Hair and hand rigs remain
present in both conditions, for three total rig nodes.

`FPlatformTime::Seconds` brackets `TickAnimation` and `RefreshBoneTransforms`.
The call supplies no tick function. Local UE 5.6.1
`SkeletalMeshComponent.cpp` requires a valid tick function and completion handle
for parallel evaluation, so this fixture evaluates synchronously. Transform
validation, counter reads and JSON generation occur outside the timed interval.
Elapsed wall time can still include preemption and is not exclusive thread CPU
time. The running game and other desktop workloads were not suspended.

The enabled counter must advance at the source scheduler's 120 Hz clock: four,
two or one steps per sampled update. Bypassed cases must not advance it. All
cases retain the accepted angular limits 6/6/10/10/3/3/5 degrees and travel limits
1.5/1.5/1/1/0.5/0.5/0.5. Non-finite output transforms fail immediately.

## Results

Times are milliseconds. Disabled/enabled columns are medians of four run
medians for the entire secondary animation update. The last column is the
median of the four within-pair differences, so it need not equal subtraction
of the preceding two columns.

| Mesh | Updates/s | Body bypassed | Body enabled | Paired added time |
| --- | ---: | ---: | ---: | ---: |
| Normal | 30 | 4.2682 | 4.4361 | 0.3531 |
| Normal | 60 | 2.6870 | 2.8986 | 0.2092 |
| Normal | 120 | 1.7878 | 2.0478 | 0.3321 |
| Facial | 30 | 4.3460 | 4.7735 | 0.5194 |
| Facial | 60 | 2.6412 | 2.9231 | 0.3977 |
| Facial | 120 | 1.8746 | 2.4198 | 0.5852 |

Variation matters: two of the 24 pair differences are negative, and individual
run p99 values reach 13.17 ms. The effect does not scale cleanly with substep
count. Preserve all raw runs instead of selecting the fastest samples. These
point estimates suggest a relatively small incremental body cost in this
fixture, but do not justify a precise runtime cost claim or a no-regression
verdict. No solver tuning or game configuration was changed from these numbers.

## Reproduction and verification

Evidence: `work/three-outfit-rig-physics/body-cost-20261015/`.

- `module/Source`, project and binary: exact compiled fixture, distinct from
  previous accepted probe projects.
- `build-command.json`, `command.json`, `regression-command.json`: build and
  read-only editor execution recipes; three corresponding exit receipts are zero.
- `inputs.json`: module, script and source-asset hashes, all unchanged after runs.
- `body-cost.json`: all 48 raw cases and 28,800 measured rows.
- `verified.json`: independently checked matrix, counters, limits, per-run
  mean/median/p95/p99/max and all paired differences.
- `graph-inputs.json`, `input-regression-verified.json`: six existing input tests.
- `cleanup.json`, `SHA256SUMS`: removal receipt and retained evidence hashes.

From the CSS repository:

```sh
python3 tools/diagnostics/verify_body_graph_cost.py work/three-outfit-rig-physics/body-cost-20261015
```

The original benchmark and regression use embedded UE Python 3.11. The verifier
uses host Python 3.14.7. No console assignment was used for frame-rate testing.
The existing live interface lacks reflected `PlayerController.ConsoleCommand`;
that read-only metadata check failed without invoking it. Arbitrarily assigning
`t.MaxFPS` would also need to preserve console priority, as described by
[Epic's console-variable documentation](https://dev.epicgames.com/documentation/unreal-engine/console-variables-cplusplus-in-unreal-engine?lang=en-US).
The editor's supplied delta times do not replace the required live 30/60/higher
frame-rate integration checks.

After both editor processes exited, the pre-recorded cleanup list removed
384,598,211 bytes of this fixture's Intermediate and derived-data cache.
Sources, binaries, captures and recipes remain. `df -h` reports root 97G and
theark 60G available both before and after, rounded. Unknown files and other
sessions' projects were not touched.

Remaining performance work includes matched accepted/candidate runtime captures,
movement/transition spikes, cloth and other outfit rigs, doubles, GPU cost and
real frame-rate coverage. This comparison is evidence for one part of that work.
