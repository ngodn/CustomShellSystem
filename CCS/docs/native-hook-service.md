# Loader-owned native pre-hook service

The loader now exposes a typed `CcsHookHost` capability appended to `CcsLoaderContext`. Core initialization checks the complete context size before reading it. The previous prefix and main core ABI version remain intact: an older core can ignore the appended capability, while a new core rejects an older short context. The installed Probe 01 has not been changed. New candidates require their matching rebuilt loader.

The service supports already-loaded native UFunctions only. It rejects Blueprint/delegate functions, missing callbacks, duplicate CCS registrations for the same function, wrong-thread requests and more than 16 retained slots. It installs no global ProcessEvent or Blueprint interception. Default/passive/menu/discovery builds currently register zero native pre-hooks. The service is a foundation for the next read-only montage-task call-site probe, not an active combat implementation.

The first serialized EngineTick callback binds the game-thread ID. Later ticks from a different thread are ignored, rather than changing the accepted ID. Registration and removal require that thread. Native dispatch rejects wrong-thread calls before entering the gate. Slot state and core invocation are serialized by the same recursive gate used by the loader's engine tick and teardown. Callback closures capture only shared loader-owned state and slots; the reloadable core function/user pointers live in `HookTarget` and are fetched at invocation time.

`HookTarget` counts active and nested invocations. Removal refuses while its callback runs. After the callback exits, detachment clears both function and user pointers before touching framework registration. A callback throwing a C++ exception is disabled and counted as failed. This does not catch invalid memory access, repair a bad parameter layout or prove an engine contract. The consumer must validate its reflected function/frame layout before registration and never retain a borrowed FFrame, locals pointer or result pointer.

Native UFunction identities are checked by object-array index, pointer, serial and name, with a required root. Registration requires an initialized positive serial and rejects all later mismatches. The core consumer must initialize/validate it first through the existing engine::WeakObject helper, which uses the verified engine soft-reference conversion when the SDK weak-serial path is insufficient. The loader never assigns serials or promotes a zero-serial identity itself. The service roots only functions it found unrooted and clears only those acquired roots after successful physical callback removal. It unregisters only its own callback ID, never all callbacks on a shared function. The pinned SDK can defer unregistration while the function executes; the service detects the callback still being present and returns failure until a later removal succeeds. The retained slot keeps the function root and a cleared core target during that interval. Core `stop()` refuses off-thread calls and refuses normal unload while service slots or invocations remain.

Before registering the first native callback, the service pins its loader DLL until process exit with GetModuleHandleEx. This is a deliberate permanent-loader lifetime rule. A late framework closure can still run loader code after the core target is detached or the mod object is shut down. It must not land in unmapped DLL code. Quiescence first closes dispatch, then clears every core target under the gate. Off-thread process shutdown performs no engine unregister/root changes. If quiescence fails or a nested callback is still active, the loader retains the core module instead of freeing executable code underneath it.

The SDK's `UnregisterHook` removes a callback but may leave the function's framework thunk/bookkeeping installed. CCS does not call `UnregisterAllHooks`, because that could delete another mod's hooks. Residual thunk cost and coexistence need live measurement, including a restart with CCS absent. No claim of zero disabled overhead is made. No new engine-byte/RVA patch is installed by this service.

Core status exposes retained slots, active invocations, stopped state, total calls, wrong-thread calls and failures. Statistics use a nonblocking gate attempt and are unavailable if it cannot be acquired. The host capability uses C integer/pointer/function types, size/version checks and no STL objects across the DLL boundary. Callers must obey the core's serialized API lifetime and host context lifetime.

## Verification and remaining work

Portable tests execute nested callbacks, refuse in-callback removal, clear late closures after freeing simulated core data, disable a throwing callback and clear callable/user pointers during quiescence. ASan/UBSan checks the late-call case. These tests cover `HookTarget`, not UE4SS's physical callback registration or live UObject lifetime. Windows cross-compilation covers the SDK/service integration.

The separate [montage-task probe 03](discovery-probe-03.md) now validates the reflected native function and input layout before arming a bounded observation hook. Physical player Outer ancestry filters its calls; grant membership, ActorInfo ownership and attack eligibility remain unverified. The candidate is not installed. Live registration, frame layout, calls, removal, cancellation, timeout and generation changes still require validation. The earlier Probe 01 verified only the task's eight parameters/56-byte signature. It did not execute the task through a hook. A swap remains unavailable until ownership, slot roles, compatibility and restore paths are demonstrated in game. Core switching and a full restoration gate also remain unfinished.
