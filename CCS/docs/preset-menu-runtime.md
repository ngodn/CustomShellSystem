# Preset naming and confirmation

Status: implemented in the experimental menu, compiled locally, not installed or clicked through in game. This extends the [asynchronous persistence foundation](persistence-runtime.md). The default build keeps the menu disabled.

The Preset page has a retained native `EditableText` field and a `Button` labeled Save. The mapped Inspect action focuses the name field. The field accepts the existing preset filename policy: 1-96 ASCII letters, numbers, dots, hyphens and underscores, excluding reserved Windows filenames and leading/trailing dots. Invalid or unreadable names show an error without submitting a write. Saving captures a copy of the active preset; it does not change the current combat bindings.

The first save always requests creation without replacement. If the worker reports an existing destination, the page shows Replace and Cancel. Cancel is selected by default. Delete uses the same explicit confirmation area. Directional navigation selects an option; Accept acts on that selection, while Cancel keeps the saved file. Pointer actions wait for button release inside its current geometry, allowing a drag outside to cancel rather than saving/deleting on mouse down. Held actions are suppressed on confirmation entry, and buttons reused for another role cannot immediately inherit a held press. Other CCS navigation actions do not operate under a confirmation. Closing, leaving CCS or replacing the menu cancels an unsubmitted confirmation.

Mapped keyboard letters are suppressed while the name field has keyboard focus, so typing cannot load, delete or switch CCS screens. Gamepad routes remain available. Escape is allowed only through an already-mapped Cancel route; no fallback key is added. Focus-mode changes reset held-key suppression. Mapped keyboard acceptance on the Save button targets saving rather than loading the selected list row. Native focus, text commit, short-click sampling, Space/Enter behavior and input coexistence still need live validation.

The editor owns a separate retained cell pool so a preset-list refresh does not move the text field to a different pooled widget. It shares the page's four-widget creation budget, including roots and button labels. Text, font, colors, enabled state and placement setters run only when their cached values change. The editor shares the page's centered uniform fit scale, so controls and text keep their proportions when the native page changes aspect ratio. The editor reads text on save, rather than serializing it each frame. File work uses the bounded worker; navigation never checks whether a file exists on disk.

## File publication

The worker validates the submitted name and preset payload, then writes to an exclusively-created temporary file in the destination directory. Process ID plus a monotonic counter separates concurrent writers, and exclusive creation protects against a collision. It retries at most eight temporary-name collisions and cleans up only the temporary file it created.

Windows publication uses `MoveFileExW` without replacement for the initial save, and enables replacement only for the separately confirmed request. The portable host implementation creates the destination with an atomic hard link for creation and uses rename for replacement. Existing files survive unconfirmed saves, including when the UI's list is stale. Concurrent creators have one winner. Unsupported filesystem operations and I/O failures return an error; there is no copy-over-existing fallback. This establishes atomic publication, not power-loss durability. See [Microsoft MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw), [POSIX exclusive creation](https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html) and [POSIX link](https://pubs.opengroup.org/onlinepubs/9699919799/functions/link.html).

## Verification and remaining checks

Host tests cover unconfirmed saves preserving existing bytes, confirmed replacement, eight concurrent creators with one complete winner, unrelated temporary files surviving replacement, failed directory replacement, cleanup and accepted writes surviving worker destruction. Both normal and ASan/UBSan runs pass. They exercise the portable file implementation and input policy, not Windows filesystem behavior or Slate interactions.

A read-only query through the existing CSSX dev bridge checked the live native defaults' naming/focus/font/button signatures. It confirmed `EditableText.GetText` returns a 16-byte text value and `SetFont` takes a 96-byte font struct. The button's `AddChild` input is lowercase `content`; this was corrected before the final build. Raw request/response IDs are retained in `CCS/work/preset-menu/native-contracts.json`. No widget was created and no setter was called by these queries.

The native font getter also returned a floating-point `Size` value (24.0 on the default editable field). Font setters now check that the reflected size is a four-byte floating-point field before writing; an integer field of the same size would otherwise reinterpret the float bits. Font object fields and offsets are checked too. Nonfinite, nonpositive or greater-than-512 font sizes are rejected before native setters to bound accidental glyph allocations. This is a rendering limit, not a fixed game-content value.

Pointer contract queries confirmed a 56-byte geometry, 16-byte absolute coordinate and one-byte result for `IsUnderLocation`. The handler copies through matching reflected properties instead of casting geometry or guessing its layout. The query results prove the declared signatures, not the button's rendered coordinates or interaction behavior.

Live checks still required: first creation, existing-name confirmation and cancellation, malformed/long names, held keys during worker completion, mouse short clicks, keyboard Tab/commit/focus, gamepad and virtual-keyboard behavior, native tab listeners, repeated close/reopen, player/menu travel, error visibility and layout/contrast at different aspect ratios. The full visual delivery gate remains incomplete. These changes are not a shipped UI or an FPS claim.
