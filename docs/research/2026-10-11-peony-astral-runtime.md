# Peony Astral runtime integration

The private CSS core now recognizes Peony's four cooked material parents and
their shared ghost companions. The Windows core builds successfully. Portable
selection and cooked shader-input checks pass. Nothing is installed, and live
texture copying, ghost rendering, cloth motion and summon timing remain open.

## Changes

The catalog adds `M_PeonyFabric`, `M_PeonyHardware`, `M_PeonyPanels` and
`M_PeonyStockings` under `/Game/CSS/eins0fx/EveSB/Peony/Materials/`.
Their companions belong to `/Game/CSS/eins0fx/Shared/Astral/Materials/`.
The selector accepts these canonical-only companions with the consolidated
pack's pose class. It refuses to invent equivalent paths in the older pack.
Existing legacy-to-canonical companion translation remains unchanged.

Catalog identities come from the independent Windows cook readback, including
each source graph's StateId. The generator validates declared source texture
names against the cooked global parameters. Runtime preparation passes those
names to the existing post-copy texture checks: six for fabric, three for
hardware, twelve for panels and none for stockings. Missing or shared
placeholder textures reject preparation through the existing fallback path.
These checks run during material preparation, not every frame.

## Copy behavior in the exact engine source

In the local UE 5.6.1 source, `MaterialInstanceDynamic.cpp:459` routes
`K2_CopyMaterialInstanceParameters(Source, true)` to
`CopyMaterialUniformParameters`. `MaterialInstance.cpp:5503` implements it by
walking from the root material through the instance hierarchy. It reads root
defaults from compiled uniform expressions and merges instance overrides.
Therefore Peony does not require replacing this call with the slower full
parameter-copy path. This source inspection is not a live-copy measurement.

Both Windows shader levels contain the required source texture uniforms.
The four ghost parents are unlit. Their compiled output uses all expected
color, mask and ORM inputs plus `CSS_AstralNoise`; the five normal-map inputs
are not used by the unlit output. Normal inputs remain in the authored graphs
and in the source-copy requirements. The first verifier incorrectly required
them in the ghost shader as well. That failed check is retained as `check1`;
the corrected verifier explicitly checks the unlit shading model before
excluding those exact normal inputs from the ghost shader requirement.
